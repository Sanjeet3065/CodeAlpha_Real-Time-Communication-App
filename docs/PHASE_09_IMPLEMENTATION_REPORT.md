## 1. Executive Summary

Phase 09 integrates CONNECTLY with real **LiveKit SFU infrastructure** (`livekit-server-sdk@2.20.0` on the Node.js/Express backend and `livekit-client@2.24.1` on the React/TypeScript frontend), verified end-to-end against a genuinely running **LiveKit SFU Server `v1.13.11`** and isolated Chrome browser contexts.

Key capabilities delivered:
- **Authoritative MongoDB-Gated Token Issuance (`POST /api/v1/meetings/:meetingCode/livekit-token`):** Enforces all 14 server-side authorization checks (including `validateRequestOrigin` CSRF protection and a post-generation `admissionStatus` + `tokenEpoch` TOCTOU re-check) before issuing a short-lived (`600s` / 10-minute) least-privilege LiveKit JWT.
- **Authoritative LiveKit Signaling Admission Gateway (`/livekit-signal`) & Signed `tokenEpoch`:** Because self-hosted OSS LiveKit Server `v1.13.11` does not enforce `revokeTokenTs` or server-side JWT revocation natively, self-hosted deployments automatically route browser signaling through CONNECTLY's pre-admission gateway (`server/src/realtime/livekitSignalGateway.ts`). Every `/rtc[/v1]/validate` request and WebSocket `Upgrade` is synchronously verified against MongoDB `Meeting` + `MeetingParticipant` + monotonic signed `tokenEpoch` BEFORE reaching LiveKit SFU — blocking removed-participant old-JWT reuse immediately across same-browser, auto-reconnect, fresh-browser, and offline-removal scenarios with **zero disruption to other admitted participants**. `LiveKitService.removeParticipant` also forwards `revokeTokenTs` for native LiveKit Cloud compatibility.
- **Strict Phase 09 Permission Boundary:** Issued LiveKit grants enable `roomJoin: true` ONLY — `canPublish: false`, `canSubscribe: false`, `canPublishData: false`, `roomAdmin: false`, `roomCreate: false`, `roomList: false`, `roomRecord: false` across ALL roles. Multi-user audio/video publishing and subscription remain strictly owned by Phase 10.
- **Deterministic Opaque Identifiers:** Maps MongoDB `Meeting._id -> cly_room_<meetingId>` and `User._id -> usr_<userId>` with zero PII.
- **Frontend Single-Room Connection Controller & Lazy Code-Splitting:** React StrictMode-safe `LiveKitRoomController` keeps tokens strictly in memory (zero Web Storage persistence), eliminates duplicate Room instances/listeners, handles all 9 connection states (including gateway `403` terminal revocation), and lazy-loads `MeetingRoomPage` (`index`: `481.84 kB`).

## 3. Defects Found & Fixed During Phase 09 Implementation & Security Audits

1. **Self-Hosted LiveKit `v1.13.11` Removed-Participant Old-JWT Reuse (Audit Round 1):** Experimental and Go-source audit proved OSS `livekit-server v1.13.11` ignores `revokeTokenTs` and allows removed participants to reconnect directly with an unexpired original JWT. Fixed via `/livekit-signal` Signaling Admission Gateway + monotonic signed `tokenEpoch` + per-participant socket termination + `revokeTokenTs` forwarding for LiveKit Cloud.
2. **Gateway Handshake-vs-Removal TOCTOU Race, Half-Open Socket Leak, Shutdown & Anti-Bypass Hardening (Audit Round 2):** Added pending handshake tracking, pre-upstream and post-handshake MongoDB revalidation, `'end'` half-open socket cleanup, `livekitSignalGateway.close()`, explicit `404` locking of alternate `/rtc*` routes, fail-closed MongoDB handling (`503`), production rejection of `LIVEKIT_SIGNAL_GATEWAY_ENABLED=false` for self-hosted deployments, and removal of client-side `VITE_LIVEKIT_URL` direct fallback.
3. **Final Distributed Revocation Correction — Transactional Sequencing, Non-Skipping Gap Fail-Closed, & Linearization Hardening (Audit Round 3 / Final):**
   - Replaced non-atomic two-step `allocateNextRevocationSeq()` + `LiveKitRevocationEvent.create()` with a **MongoDB ACID transaction** (`session.withTransaction`, `majority` read/write concern) holding the WiredTiger exclusive lock on `LiveKitRevocationCounter` until commit/abort, with zero silent non-atomic fallback in production (`LIVEKIT_REVOCATION_TRANSACTION_REQUIRED` / `LIVEKIT_REVOCATION_TRANSACTION_FAILED`).
   - Removed silent gap-skipping in `advanceExpiredGaps()`; replaced with `evaluateSequenceGaps()` which never marks missing sequences dispatched, never silently discards late-arriving events, detects both mid-stream and TTL trailing counter gaps, and transitions fail-closed (`503` + active socket teardown) if a gap persists beyond `gapFailClosedGraceMs`.
   - Added durable MongoDB `LiveKitRevocationCursor` checkpointing (`lastContiguousSeq` + Change Stream `resumeToken`) and `ChangeStreamHistoryLost` recovery.
   - Coupled `removeParticipant()` and `endMeeting()` with revocation publishing inside one MongoDB ACID transaction on Replica Sets; added guaranteed local socket teardown + LiveKit SFU eviction + fail-closed error handling on standalone publish failure + defense-in-depth `revalidateActiveSockets()` sweep on gateways.
   - Closed meeting-termination and expiration races by adding post-fence `Meeting` status/`expiresAt` revalidation inside `claimSignalingAdmissionFence()`, incrementing `tokenEpoch` + `signalFenceVersion` on `endMeeting()`, `findMeetingAndEnforceExpiration()`, `admitParticipant()`, and `joinMeeting()` re-admission, and publishing `MEETING_ENDED` on meeting expiration.
4. **Origin CSRF Guard & Query Token Redaction:** Mounted `validateRequestOrigin` explicitly on `POST /:meetingCode/livekit-token` and added query-parameter redaction (`access_token=[REDACTED]`) in `requestLogger.ts`.
5. **Initial Bundle Bloat Prevention:** Lazy-loading `MeetingRoomPage` kept the root initial bundle at `481.84 kB`.
6. **Narrow Mobile Header Overlap (`320px`/`390px`):** Fixed in `MeetingHeader.tsx` (`min-w-[175px]` + `flex-wrap`) with verified `0px` horizontal overflow.
7. **ESLint Zero-Warning Cleanliness:** `0 errors, 0 warnings`.
